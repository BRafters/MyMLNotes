Supervised ML algorithms are amazing tools capable of making predictions and classifications. It is important however, to ask yourself how accurate those predictions are. It is possible that every prediction your classifier makes is actually wrong!

- We can leverage the fact that supervised ML algorithms, by definition, have a dataset of pre-labeled datapoints
- To test the effectiveness of your Supervised ML algorithm, we can split this pre-labeled data into:
    - A set of Training Data
    - A set of Validation Data
    - A set of Test Data

### Training Set vs. Validation Set

- The **Training Set** is the data set that the ML algorithm will learn from
    - Learning looks different depending on the ML algorithm you’re using. IE:
        - When using **Linear Regression**, the points in the training set are used to draw the line of best fit
        - In **K-Nearest Neighbours**, the points in the training set are the points that could be the neighbours
- After training using the **Training Set**, the points in the **Validation Set** are used to compute the accuracy or error of the classifier
- The key insight here is we know the true labels of every point in the **Validation Set**, but we temporarily pretend we don’t
    - We can use every point in the validation set as our classifier
    - We’ll then receive a classification of that point
    - We can then peak at the true label of the validation point and see whether we got it right or not
    - If we do this for every point in the validation set, we can compute the validation error
- Validation error may not be the only metric we’re interested in 
    - A better way to judge the effectiveness of a machine learning algorithm is to compute its Precision, Recall, and F1 score
### How to Split

Sometimes your dataset is too small, to the point that splitting it 80/20 will result in a large amount of variance

- One solution is to perform **N-Fold Cross Validation**
- The idea is we do this process N times and average the accuracy
- For example; in **10-Fold Cross Validation**, we make the validation set at the first 10% of data, and calculate accuracy, precision, recall, and F1 score
    - We then make the **Validation Set** the second 10% of the data, then calculate these statistics again
    - We can do this process 10 times, and every time, the validation set will be a different chunk of data
    - If we average all of the statistics, we will have a better sense of how our model does an average

### Changing The Model / Test Set

Understanding the accuracy of your model is invaluable because you can begin to fine tune the parameters of your model to increase its performance.

- In the K-Nearest Neighbours algorithm, you can watch what happens to accuracy as you increase or decrease K
- Once you’re happy with your model’s performance, you can then introduce the **Test Set**
- This is the data you’ve partitioned away at the very start of your experiment
    - It’s meant to be a substitute for the data in the real world that you’re actually interested in classifying
- The **Test Set** functions similarly to the **Validation Set**, except you never touched this data while building or tuning your model
- By finding the accuracy, precision, recall, and F1 score on the test set, you get a good understanding of how well your algorithm will do in the real world
